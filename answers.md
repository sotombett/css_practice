# Ответы на вопросы

1. В чём разница между селектором по классу и по ID с точки зрения специфичности и возможности повторного использования?

Класс имеет специфичность `0,0,1,0` и может применяться к любому числу элементов на странице. ID имеет специфичность `0,1,0,0` и должен быть уникальным в пределах документа. Из-за этого для оформления используют классы (их можно переиспользовать и комбинировать), а ID - в основном для якорей и JS-хуков.

2. Как работает каскад в CSS и в каком порядке применяются стили при конфликте правил?

Каскад - это алгоритм выбора победившего правила. Порядок приоритетов:

1. `!important`.
2. Происхождение: стили браузера, пользовательские, авторские.
3. Специфичность селектора.
4. Порядок объявления: при равной специфичности выигрывает то правило, что написано ниже.

Если ничего не подошло, то берётся унаследованное или значение по умолчанию.

3. Рассчитайте специфичность для селекторов

`ul li.important` - `0,0,1,2` (0 ID, 1 класс, 2 тега).
`#site-title` - `0,1,0,0` (1 ID).
`.content > .featured-post` - `0,0,2,0` (2 класса).

4. Какие свойства в CSS наследуются по умолчанию, а какие нет?

Наследуются: `color`, `font-family`, `font-size`, `line-height`, `text-align`.

Не наследуются: `margin`, `padding`, `border`, `background`, `width`, `display`.

5. Как работает селектор `>` и чем он отличается от селектора потомков (через пробел)?

`a > b` выбирает только прямых потомков элемента `a`, которые являются `b`, а селектор `a b` выбирает всех потомков любого уровня вложенности. Например, `ul > li` затронет только `li` верхнего уровня, а `ul li` ещё и `li` внутри вложенных списков.

6. Для чего используются псевдоклассы `:hover` и `:nth-child()`?

`:hover` применяет стиль при наведении курсора (подсветка ссылок, кнопок, строк таблицы). `:nth-child()` выбирает элементы по порядковому номеру среди соседей  например, «зебра» в таблице (`tr:nth-child(even)`), стилизация каждого третьего блока, выделение первого и последнего элемента без отдельных классов.

7. Что делает правило `!important` и почему его следует использовать с осторожностью?

`!important` повышает приоритет объявления до максимального, перебивая обычные правила и правила с более высокой специфичностью. Использовать с осторожностью, потому что он ломает естественный каскад, усложняет поддержку кода, мешает переопределению стилей темами и сторонними библиотеками, и часто приводит к появлению ещё одного `!important` «сверху».

8. Как псевдоэлементы `::before` и `::after` расширяют возможности CSS и какой контент они могут содержать?

Они создают виртуальные элементы до и после содержимого реального тега, не добавляя разметку в HTML. Содержимое задаётся через свойство `content`:

```css
.icon::before { content: "★"; }
.card::after  { content: ""; display: block; clear: both; }

9. В каком порядке браузер применяет CSS-правила при одинаковой специфичности селекторов?

При одинаковой специфичности выигрывает правило, объявленное позже в итоговом потоке CSS. Порядок с учётом источника такой:

1. Стили браузера (user-agent).
2. Пользовательские стили.
3. Авторские стили.

Внутри авторских чем ниже строка, тем выше приоритет. Поэтому важно следить за порядком подключения `<link>` и расположением `<style>` в документе.

10. Как инструменты разработчика в браузере помогают анализировать и отлаживать CSS-код?

Инструменты разработчика (открываются на F12) позволяют:

- Просматривать и редактировать CSS в реальном времени.
- Видеть, какие правила применились, а какие перечёркнуты как перебитые.
- Определять источник правила (файл и номер строки).
- Анализировать блочную модель элемента (margin, border, padding, content).
- Проверять вычисленные значения на вкладке Computed.
- Эмулировать мобильные устройства и состояния (`:hover`, `:focus`, `:active`).
- Находить причины конфликтов стилей и отлаживать каскад.
